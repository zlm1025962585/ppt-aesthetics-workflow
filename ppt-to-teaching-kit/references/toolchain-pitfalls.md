# 工具与交付中的实际边界

## 运行时优先

- Codex 中生成 PPTX 时读取当前演示文稿技能，生成 DOCX 时读取文档技能，并通过可用的 `load_workspace_dependencies` 加载运行时。不要硬编码缓存版本、工具全名或另一客户端的命令。
- 当前演示文稿技能要求 Artifact Tool 时按其规定生成；不要因为本包有旧 Python 脚本就绕开宿主要求。其他平台选择其实际可用工具并保持编辑性。
- `.slide` 是旧客户端的 DSL，不能直接交给不支持它的工具编译。

## 字体与尺寸

- 核对字体实际可用性，中文文本同时考虑东亚字体。图片里的书法字不是可编辑标题。
- Artifact Tool 的数值几何与 `fontSize` 通常是 CSS px；PPT pt 与 EMU 需统一换算。16:9 的 1280×720 对应 12192000×6858000 EMU，避免用近似英寸引入边界误差。
- 不拉伸图片；对正文、证据和表格按实际裁切结果复核，不依赖 fit 参数名称猜测结果。

## PDF 与媒体

截图型 PDF 可能完全没有可提取文字，先看渲染页面；有需要时使用 OCR，并对诗句、姓名、选项、答案逐字复核。PDF 页面中显示播放器截图，不等于 PDF 带有可恢复视频。

重建主要内容为原生文字，去掉截图工具栏；学生原作与照片保留证据属性。裁切证据时看完整文字行与关键内容，不能只看自动边界检查。

## Windows 与路径

中文路径、长文本和配置优先写入 UTF-8 文件，由脚本读取；避免在跨解释器的长命令中直接嵌套大量中文与引号。Node 模块和子进程要继承所需的运行时模块路径。

## 验证与修订

- 按当前工具要求执行操作标记和最终校验。候选稿、最终稿、验证回执使用明确路径；每次修订使用新的最终文件名与回执名，防止 EEXIST 或误交旧稿。
- 校验须覆盖实际导出文件，不能拿上一次 PASS 对新文件作证。
- 用渲染器检查全部页；共享样式更新后重新查看受影响页。没有打开 PowerPoint 时不要声称已在 PowerPoint 实测。
- `visual_check.py` 是旧模板的视觉底线检查，不能判断内容是否空、插画是否贴题或整套是否有节奏。`run_all.py` 的结论也不替代逐页自审。
- `render_preview.py` 是 Windows PowerPoint 的可选工具；没有 PowerPoint 不等于没有其他渲染路线。报告实际完成的检查与限制。

生成物按用户指定位置保存；未指定时遵循当前工作区输出约定，中间文件与检查记录留在工作区。
